Version 1, 2026-10-10. Author lens: the implementer who builds this on v0.1.0 in a few hours, keeps it at
60 fps on an iPhone from `file://`, and proves every shipped level solvable. Binding order: `docs/OWNER-NOTES.md`

## 0. Summary and decision log

**One paragraph.** The v0.1.0 board grows from "slots of item ids" to "compartments with a front row of item ids
plus a queue of back layers (type codes)", gains two kinds of take-only conveyor lanes (vertical side lanes, a
horizontal bottom lane), lock counters and a level-wide bunny charge. Conveyor *motion* lives only in the view (CSS
keyframe animations, zero JS per frame); the pure rules see a lane as a time-independent pool of take-only cells.
That one choice makes the solver, the undo stack, the save format and the tests ignore time, and it is what lets
us prove solvability. Levels are generated by one pure generator shared by `scripts/build-levels.js` (bakes L1-150
per branch with a certificate) and the browser (L151+ at runtime with a node-budgeted, deterministic gate).

| # | Decision | Why (one line) |
|---|---|---|
| D1 | Evolve `board.js`/`game.js`; back layers stored as type codes, item ids minted on reveal | Existing move/match/canMove code keeps working on the front row unchanged |
| D2 | Centre rack = R rows x 2 columns of 3-slot compartments, optional top and bottom single compartment, C = 2R+t+b, 4..10 | Owner's decoded layout (screenshots Lv.513) |
| D3 | Whole-layer advance, depth up to 6, only front + dimmed next layer drawn, deeper layers shown as pips (count only) | Owner; pips give the count without showing products |
| D4 | Lanes are take-only pools in the model; motion is a pure CSS animation in the view | Solvability is then time-independent; no per-frame JS; battery |
| D5 | Lock = chain + counter N, opens after N matches anywhere (every match counts 1, bunny clears count 1) | Owner (number = matches) + wiki CellLock: "each match-3 decreases by 1", default 4 |
| D6 | Golden bunny is *collected* (auto, when it surfaces) into a counter and *spent* on any unlocked compartment to clear its front row | Never blocks a slot, so the solver can ignore it; matches the original's HUD counter going 0 -> 2 |
| D7 | Orphans: when fewer than 3 copies of a type remain anywhere, all reachable copies vanish; win = no matchable item left | Owner's rule; wiki GameplayMechanics: IsCompleteLevel = no match/take/reveal left |
| D8 | Hammer, Shuffle, Wand dropped; kit = Undo, Goldhase, Einfrieren (timed) / Tipp (relaxed) | Bunny covers the hammer's job; fewer mechanics to build, test and explain |
| D9 | Undo unlimited in both branches; relaxed free, timed costs 5 s of clock per undo | One mechanism, each branch pays in its own currency; stuck is never terminal |
| D10 | Two knob tracks: relaxed hardens structure (layers, locks, types, F0), timed hardens clock + lane speed + horizontal lane | Owner's branch definitions |
| D11 | Bake L1-150 per branch into `levels-data.js` (~80 KB) with witness certificates; L151+ generated at runtime, deterministic, fallback = transformed baked level | Curated opening, infinite tail, no workers/fetch, file:// safe |
| D12 | Gate budgets are node counts, never milliseconds; integer-only RNG and playout weights | Level N is bit-identical on every device |
| D13 | Speed and time limit are *derived at runtime* from (branch, level, structure), not baked | Retune on the owner's iPhone without rebaking |
| D14 | Render loop runs only while timed PLAY, an animation or the combo bar runs; relaxed with moving lanes stays idle (CSS) | 60 fps and a cool phone |
| D15 | RULES_VERSION 1 -> 2, save `v: 2`; old runs are banked to the top 10 and dropped | Board snapshots change shape |

**Rejected (one line each).** Canvas renderer (DOM is enough for <= 160 nodes, keeps hit-testing and CSS juice).
JS-driven lane motion (24 transform writes per frame for nothing). Runtime-only generation for all levels (owner
wants curated quality early). Reverse-construction generator (research: 3/40 successes at density). Side cells with
depth > 1 in v1 (owner says bars come after one take; see Q1). Hammer/Shuffle (overlap with bunny and undo).
Same boards in both modes (research decision 4; owner's branches harden different knobs). A time-based gate.

**Where this deviates from RESEARCH.md "Decisions at a glance"** (owner wins unless noted as lens):
- #2 depth max 3 -> 6 (owner). Moving shelves, golden item -> v1 (owner).
- #4 same boards in both modes -> per-branch tracks (owner's branch notes).
- #5 bake 500 -> bake 150 per branch + runtime tail (lens: owner wants infinite and harder; transforms alone plateau).
- #7 time `sPerItem` 7.0-5.0 -> 4.0-2.5 plus lane wait (owner: about 6 min on a ~110-item Lv.513 board).
- #9 kit Undo/Hammer/Shuffle/Freeze/Hint -> Undo/Goldhase/Freeze|Hint (lens: smallest set).
- Grid 3 columns -> 2-column rack with top/bottom singles (owner).

## 1. Game model, formal

### 1.1 Terms

| Symbol | Meaning |
|---|---|
| C | centre compartments, `C = 2R + t + b`, R in 2..5, t,b in {0,1}; index order: top single, then rows left-to-right, then bottom single |
| front(c) | 3 slots of compartment c, each an item id or 0 (fixed positions, no compaction, as v0.1.0) |
| back(c) | queue of layers behind the front, `back[0]` = the dimmed "next" layer, length 0..5 (depth = 1 + length <= 6) |
| layer | `[t|null, t|null, t|null]`, 1..3 non-null type codes; null = hole that keeps its slot position |
| lock(c) | 0 = open, else the match count at which c opens (`lockAt`), shown as `lockAt - matches` |
| lane | `{ axis: 'v'|'h', side: 'L'|'R'|'B', cells: [Cell], appearAt: matches (0 = from start) }` |
| Cell | `{ id, item: itemId|0, barred: bool }` (v1 depth 1; Q1) |
| F | free front slots in unlocked centre compartments |
| bunnies | golden bunnies collected and not yet spent (level-scoped counter) |
| matches | matches made in this level (drives locks and lane appearance) |

### 1.2 Centre rack

- Two columns of 3-slot compartments; a top single and a bottom single compartment are centred above and below.
  Every compartment has exactly 3 slots (the "single" refers to it standing alone in its row, as on Lv.513).
- Shapes used: `2` (C=4), `3` (6), `3+t` (7), `3+t+b` (8), `4+t` (9), `4+t+b` (10). Visual rows = R+t+b <= 6.
- Front row = layer 1. Products of `back[0]` become reachable only when the front holds 0 items (R7).
- Drawn: front at full brightness, `back[0]` behind it darkened (one overlay div per compartment), deeper layers
  never drawn; a pip row on the plank shows `back.length - 1` (0..4 pips), so the player knows depth, not content.

### 1.3 Layers

- Layer sizes: front 1..3 (start), back layers 1..3, never 0, never 3 identical (generator invariant G3).
- Whole-layer advance: when front(c) is empty and back(c) non-empty, `back.shift()` becomes the front; each non-null
  code gets a fresh item id at the same slot index; holes stay holes. Cascades: if the new front is empty after
  orphan/bunny removal, advance again (loop, bounded by depth).
- Products reachable for play: centre fronts of unlocked compartments, unbarred cells of appeared lanes.

### 1.4 Locks

- `lockAt` = N (3 or 4, from data). Counter shown = `max(0, lockAt - matches)`. At `matches >= lockAt` the chain
  falls and the compartment behaves normally. While locked: no drops into it, no picks from it, no bunny target.
  Its front is full at start (G6) and its dimmed next layer is drawn under the chains (as on the screenshot).
- No ad, no gold, no skip (owner).

### 1.5 Side shelves (lanes)

- Vertical lanes left and right of the rack: a loop of `n` single-slot cells scrolling up (out at the top, back in
  at the bottom). Horizontal lane under the rack: a loop scrolling left (timed only, section 4).
- Take-only: a lane item can be moved to an empty front slot of an unlocked centre compartment; nothing can be
  dropped onto a lane or put back. After a take the cell is `barred` (bars slide down from above, 250 ms) and stays
  closed for the rest of the level. A barred cell keeps travelling with the loop (it is part of the strip).
- Loop length: static lanes have `n = rows` (every cell visible, no wrap); moving lanes have `n >= rows + 3`, so at
  least 2 cells are off-screen and the wrap jump is never visible (E6).
- Speed `v` in cells per second, derived at runtime (section 4.4). Period `P = n / v` seconds.
- **Model abstraction (the key engineering fact):** in the pure state a lane is a set of cells, each takeable at any
  time while unbarred. Motion only decides *when* a cell is on screen. Because the loop is periodic, any abstract
  sequence of takes is realisable by waiting at most `P` seconds per take. Relaxed has no clock, so waiting is free;
  timed pays the wait out of the time limit, which includes a wait allowance (4.4).
- Horizontal lanes may appear mid-level: `appearAt = k` means the lane slides in after k matches (owner: "later in
  a level"). Before that, its items do not exist for rules, stuck test or solver.

### 1.6 Golden bunny

- Placed by the generator in a hole of a back layer (`'*'` in data), never in a front at start, never in a lane cell
  in v1. It does not occupy a slot for the rules: when its layer reaches the front, the bunny flies to the
  Goldhase button (600 ms), `bunnies += 1`, the slot stays empty.
- Also earned: `+1` the first time the chain reaches 5 in a level (both branches).
- Spend: tap the Goldhase button (it arms, legal targets glow), tap or drag onto an unlocked centre compartment with
  >= 1 front item. Effect: every front item of that compartment vanishes (bunny animation), `matches += 1` (locks
  and lane appearance count it), then reveal (R7) and orphan sweep (R9). It is one move (relaxed counts it).
- Tap the armed button again or tap outside the rack to disarm.

### 1.7 Orphans

- `remaining[t]` = copies of type t anywhere: fronts (incl. locked), back layers, lane cells (appeared or not).
- Type t is an orphan when `1 <= remaining[t] <= 2` (no triple can ever be formed again). Only the bunny can create
  orphans (all types are dealt in multiples of 3 and every match removes exactly 3).
- Sweep: all copies of orphan types in centre fronts (locked ones too) and unbarred lane cells vanish (fade 300 ms,
  no points, lane cells get barred). Copies in back layers vanish the moment their layer reaches the front.
- Win: `matchable = sum over t with remaining[t] >= 3 of remaining[t]` is 0. Hidden orphans may remain behind; the
  level still counts as solved (owner; wiki IsCompleteLevel).

### 1.8 Free space (what happens when the rack is full)

- `progressPossible(b)` (exact one-step test, extends RESEARCH M11 with lanes and bunny):

```js
// Vc[t]: copies in unlocked centre fronts; Vs[t]: copies in unbarred cells of appeared lanes (on or off screen)
// H: items in back layers of unlocked compartments; F: free front slots of unlocked compartments
function progressPossible(b) {
  if (b.bunnies > 0 && anyUnlockedFrontNonEmpty(b)) return true;           // spend the bunny
  for (var t in typesPresent) {
    if (Vc[t] >= 3 && F >= 1) return true;                                  // gather inside the rack
    var need = 3 - Vc[t];
    if (need > 0 && Vs[t] >= need && F >= need) return true;                // take `need` copies from lanes
  }
  return F >= 3 && H > 0;                                                   // empty a front to reveal
}
```

  Proof sketch: with one hole, centre fronts can be permuted arbitrarily (M11); a triple needing `s` lane copies
  needs `s` holes in one compartment; a reveal needs a front of k items emptied into `F-(3-k) >= k` holes, so F >= 3;
  locks and appear-later lanes open only through matches, which the first two lines already cover.
- When false the board is **stuck** (event `stuck`, not terminal):
  - Relaxed: sheet "Kein Platz mehr" with **Rückgängig** (unlimited) and **Neu starten** (same board).
    Nothing is recorded as a loss.
  - Timed: non-modal banner "Kein Platz mehr" over the rack with **Rückgängig (-5 s)** and **Lauf beenden**; the
    clock keeps running. The run ends by time or by the player, never by the banner itself.

### 1.9 Undo

- Every state-changing action (move, take, bunny spend) pushes `snapshotBoard(b)` plus `{score, levelScore, combo,
  comboLeftMs, comboMovesLeft, bunnies, bunnyEarned, matches}` onto `g.undo` (cap 100, oldest dropped).
- `undo(g)` pops one entry and restores it exactly: unbars a lane cell, un-reveals a layer, re-locks a compartment,
  restores bunnies and score. It never rewinds the clock, never lowers `moves`, and in timed mode subtracts 5000 ms
  from `timeLeftMs` (floored at 1000 ms so undo never causes the timeout by itself).
- Undo after a reveal shows what was in the next layer; accepted (it costs moves or clock).
- The undo stack is not persisted; after reload it is empty.

## 2. Rules, tick order, events

### 2.1 Rules

- **R1** Pick: only front items of unlocked centre compartments and items of unbarred cells of appeared lanes can be
  picked. Items in back layers, locked compartments and barred cells cannot.
- **R2** Drop targets are empty front slots of unlocked centre compartments other than the source compartment.
  Lanes are never targets. The item lands in the slot under the finger if empty, else the nearest empty slot.
- **R3** An illegal drop springs back in 180 ms (`SPRING_MS`); a lane item flies back to its cell's *current*
  on-screen position. Not a move, no undo entry, no combo effect.
- **R4** Take: a legal drop of a lane item bars its cell (R4 is a move, `moves += 1`).
- **R5** Match: 3 identical items in one front row clear (`MATCH_MS` 320). `matches += 1`.
- **R6** Locks: after every `matches` change, each compartment with `lockAt <= matches` unlocks (event `unlock`);
  each still-locked compartment emits `lockTick` with its new counter. Lanes with `appearAt <= matches` appear.
- **R7** Reveal: a centre compartment with an empty front and non-empty `back` advances one layer; order: target
  compartment first, then source compartment, then any compartment emptied by R9; repeat until stable.
- **R8** Bunny: a `'*'` arriving in a front is collected (`bunnies += 1`, event `bunnyFound`), its slot stays empty.
- **R9** Orphans: after R5-R8, sweep orphan types (1.7); then R7 again for fronts the sweep emptied.
- **R10** Win: `matchable == 0` -> event `cleared`, status `won`. Checked after the full resolution of an action.
- **R11** Stuck: else if `!progressPossible` -> event `stuck` (once per distinct state; `unstuck` after undo).
- **R12** Combo, timed: each match `chain += 1`, refill `comboLeftMs = 5000`; on expiry `comboEnd`, `chain = 0`.
- **R13** Combo, relaxed: each match `chain += 1`, `comboMovesLeft = 3`; each move without a match decrements; at 0
  `comboEnd`, `chain = 0`. No clock.
- **R14** Chain 5 first reached in a level: `bunnies += 1`, event `bunnyEarned` (once per level).
- **R15** Bunny spend: 1.6; counts as a move and as one match for R6, scores 0, neither raises nor breaks the chain.
- **R16** Clock (timed): starts on the first pointerdown on the board after the level appears; `timeLeftMs`
  decreases in `tick` unless frozen. At 0: first time -> `timeout` card with free "+30 s" (once per level) or
  "Lauf beenden"; second time -> run over.
- **R17** Freeze (timed, 1 per level from L10): clock stops 15 s; combo window keeps draining.
- **R18** Hint (relaxed, 3 per level from L10): shows the next move of a solver line (section 3.6).
- **R19** Moves: R4 takes, plain moves and bunny spends add 1; undo, freeze, hint add 0.
- **R20** Pause stops the clock, the combo window and the lane animations (`animation-play-state: paused`).

### 2.2 Action resolution order (pure, synchronous; `game.js`)

```
act(g, action):                               // action = move | take | bunny
  if g.status != 'playing' or !legal(action) -> return []
  pushUndo(g); g.moves += 1; ev = []
  apply(action)                               -> move | take(+bar) | bunnyUsed
  if action != bunny and matchIn(target)      -> match, score, chain (R5, R12/R13, R14)
  if action == bunny                          -> matches += 1
  revealLoop([target, source])                -> reveal*, bunnyFound*        (R7, R8)
  sweepOrphans()                              -> orphan*, bar*, reveal*      (R9, then R7)
  applyThresholds()                           -> lockTick*, unlock*, laneAppear*  (R6)
  if relaxed and no match this action         -> comboMovesLeft--, maybe comboEnd
  if matchable == 0 -> finishWon -> cleared   (R10)
  else if !progressPossible -> stuck          (R11)
  return ev
```

### 2.3 Tick order (`game.tick(g, dtMs)`, dt clamped to 100 ms by the loop)

1. If status != 'playing' or the level has not started (no first touch): return [].
2. `elapsedMs += dt`.
3. Freeze: if `freezeLeftMs > 0`: decrement; on reaching 0 emit `freezeEnd`; skip step 4 for this tick.
4. Timed clock: `timeLeftMs -= dt`; at <= 0 emit `timeout` (status `'timeout'`, resumable by `extend(g)`).
5. Timed combo: `comboLeftMs -= dt`; at <= 0 emit `comboEnd`, `chain = 0`.
6. Nothing else: lanes are not in the pure tick (D4).

### 2.4 Events (extends move/match/combo/score/cleared/deadlock/timeout/comboEnd)

| Event | Payload | Consumers |
|---|---|---|
| `move` | item, product, from, fromSlot, to, toSlot | board view, sound `drop` |
| `take` | item, product, lane, cell, to, toSlot | lanes view (reparent img), sound `drop` |
| `bar` | lane, cell, reason ('take'/'orphan') | lanes view (bars slide down), sound `clank` (soft) |
| `match` | comp, product, items, slots, chain, points | fx, sound `match(chain)`, HUD |
| `combo` / `comboEnd` | chain, multiplier | HUD bar or pips, sound |
| `score` | delta, score | HUD |
| `reveal` | comp, layer: [{id, type, slot}], depthLeft | board view (dim -> front), sound `swish` |
| `lockTick` | comp, left | lock badge pop |
| `unlock` | comp | chains fall, sound `unlock` |
| `laneAppear` | lane | lanes view slides the lane in |
| `bunnyFound` / `bunnyEarned` | comp, slot / chain | fly to Goldhase button, toast |

## 3. Solvability and the proof

### 3.1 What "solvable" means here

A level is solvable when a sequence of moves and takes, **without** undo, bunny, freeze or hint, reaches
`matchable == 0`. Bunnies are ignored by the solver: they sit in holes (no slot cost) and spending one only
removes items, so they are pure slack for the player. Time is ignored by lemma 1.5 (periodic lanes); the timed
limit is checked separately by simulation (3.5).

### 3.2 The abstract solver state (`solver.js`)

```js
// compiled once per level by compile(levelSpec); never touches the DOM or time
S = {
  front: Int8Array(C*3),        // type code + 1, 0 = empty (slot order irrelevant -> sorted for keys)
  ptr:   Int8Array(C),          // next back layer index per compartment
  layers: [[Int8Array(3)...]],  // static, shared between states
  lockAt: Int8Array(C),         // 0 = open from start
  pool:  Int16Array(T),         // lane copies per type (appeared lanes), take-only multiset
  later: [{appearAt, counts}],  // lanes that appear after k matches
  matches: int, left: int       // left = matchable items remaining
}
moves(S) = centre->centre (front type of unlocked a -> unlocked b != a with a hole)
         + pool->centre       (type t with pool[t] > 0 -> unlocked b with a hole)
key(S)   = per open compartment: ptr + sorted front; finished compartments (ptr at end) sorted together;
           pool counts; min(matches, maxPendingThreshold)
```

Abstracting lane cells into per-type counts is exact because all cells of a lane are interchangeable for the rules
(any of them can be taken at any time); this collapses up to 27 cells into <= 30 counters and is the main reason the
search stays cheap with lanes.

### 3.3 Search: the gate

Evolution of `docs/research-proto/solver.js` (`solveP`, `agent`), moved into `src/game/solver.js` (pure, ES2018):

1. **solveP**: iterative DFS, move ordering by `scoreMove` (complete triple 1000, make pair 300/120, break pair -200,
   empty a front with layers behind +60, pollute -60, *take from pool* -40 unless it completes a triple or pair),
   memo `key -> best remaining shuffle budget`, progress bound P = 4 plain moves between progress events (match,
   reveal, unlock). Sound: a returned path is a real solution. Budget in **nodes**.
2. **Playouts** (only if 1 returns "budget hit"): up to 64 agent playouts, softmax replaced by an integer table
   `W = [1000, 607, 368, 223, 135, 82, 50, 30, 18, 11, 7, 4, 2, 1]` indexed by `min(13, (best - score) / 40 | 0)`,
   RNG = mulberry32 (integer). First win = witness.
3. **Replay check**: the witness is replayed through the real `SS.board`/`SS.game` rules from the decoded level;
   accepted only if that ends in `cleared`. This closes any gap between the solver model and the game.

Budgets (nodes; desktop Node rates from the research prototype: ~1 µs/node-op, phone ~4x slower):

| Use | Node budget | Desktop p95 | iPhone 12 p95 (est. x4) | Where it runs |
|---|---|---|---|---|
| Bake gate per attempt | 400k | 600 ms | - | build script |
| Runtime tail gate per attempt | 40k | 60 ms | 240 ms | browser, sliced 2k nodes per slice |
| Hint (relaxed) | 25k | 40 ms | 160 ms | browser, sliced |
| Stuck test | O(items), no search | 0.02 ms | 0.1 ms | every action |

### 3.4 The proof (certificates)

The owner asked for proof that the generator only emits working levels. The proof is constructive and machine-checked:

1. **Certificate per baked level.** `build-levels.js` writes `tests/fixtures/witnesses-<gen>.json`:
   `{ branch, level, sha1(levelString), moves: "3a>7,Pc>2,..." }`, one token per move: source compartment
   (base 36) or `P` for a lane take, the type code, `>`, target compartment. Not shipped (about 120 KB), kept in the repo.
2. **Checker = the shipped rules.** `tests/levels.test.js` replays every certificate through `SS.game` (decode level,
   apply moves, assert `cleared`, assert no illegal move). 300 levels x ~70 moves = ~21k actions, < 3 s in Node.
   Because the checker is the production rule code, not the solver, a solver bug cannot fake a proof.
3. **Runtime levels.** The browser generator emits a level only after step 3 of 3.3 succeeded on the device (the
   replay *is* the check), else it emits the fallback (3.7), which is a baked level under a solvability-preserving
   transform (relabel types, permute compartments of the same shape class, permute lane cells). Transform lemma:
   all three are symmetries of the rules, so the transformed certificate (relabelled, re-indexed) is a solution.
4. **Determinism makes the browser proof reproducible.** Generation uses only integer RNG and node budgets, so
   `node scripts/prove-levels.js relaxed 151 2000` recomputes exactly the levels every phone will build, replays
   their witnesses and writes `docs/proof/relaxed-151-2000.txt` (counts, fallbacks, sha256 of all level strings).
   `tests/levels.test.js` pins the hash of L151-160 per branch so a code change that alters tail levels fails CI.
5. **Lane lemma** (1.5) and **bunny lemma** (bunny only removes items and occupies no slot; after any removal the
   solver may continue from the new state, and the player can undo) complete the argument for the full model.

### 3.5 Generation (shared pure `gen.js`)

```
generate(branch, L, attemptLimit, nodeBudget):
  k = knobs(branch, L)                                  // section 4
  for attempt in 0 .. attemptLimit-1:
    rng = SS.rng.create('gen' + GEN_VERSION + '-' + branch + '-' + L + '-' + attempt)
    sizes  = frontSizes(k.C, k.F0, rng)                 // F0 holes spread over fronts, no front empty (G1)
           + backSizes(k, rng)                          // layer 2 on l2n comps, layers 3..depth on deepN comps
    side   = k.lanes * k.cells + k.hCells               // every lane cell filled
    total  = sum(sizes) + side; fix total % 3 by shrinking random back layers (never below 1)
    T      = min(k.types, total/3); deal = each type x3, extra triples round-robin (x6)
    shuffle deal into slots; re-deal any layer that is a triple (max 50 tries)   (G3)
    locks  = pick k.locks comps among the 2-column rows whose front is full     (G6)
    bunny  = put k.bunny '*' into holes of back layers 2..3 of distinct comps     (G7)
    if frontHasTriple or !progressPossible(start) or F0 < 1: continue
    w = gate(level, nodeBudget)                          // 3.3 steps 1-3
    if !w: continue
    if baking: m = metrics(level, 20 agent playouts); if !accept(m, k.tag, L): continue
    par = ceil(min(w.length, bestPlayout) * (depth == 1 ? 1.10 : 1.25))
    return { string: encode(level), par, witness: w, attempt }
  return null                                            // build: widen window 10 points and log; runtime: fallback
```

Invariants checked by `levels.test.js` for every baked level: G1 no front empty at start; G2 item count % 3 == 0 and
every type count % 3 == 0; G3 no layer is a triple; G4 F0 >= 1 and `progressPossible(start)`; G5 moving lanes have
`n >= rows + 3`, static lanes `n == rows`; G6 locked compartments start with a full front; G7 bunnies only in back
layer holes, at most one per compartment; G8 depth <= 6; G9 types <= 30.

Acceptance windows (agent win rate over 20 playouts, bake only; RESEARCH 3.5 extended for the new knobs):

| Block | Normal | Schwer | Sehr schwer | Pause / Tutorial |
|---|---|---|---|---|
| L1-10 | 85-100% | 70-95% | 55-90% | 95-100% |
| L11-30 | 70-100% | 55-85% | 40-80% | 90-100% |
| L31-60 | 55-90% | 35-70% | 20-60% | 85-100% |
| L61+ | 45-85% | 25-65% | 8-45% | 80-100% |

### 3.6 Hint uses the same search

`hint(g)` compiles the current state, runs `solveP` with 25k nodes in 2k-node slices (one per frame, spinner after
100 ms). Result: highlight source item and target compartment for 3 s. No witness found -> "Kein Weg gefunden:
Rückgängig oder Neustart" and the charge is kept.

### 3.7 Baked vs runtime, and failure handling

| Range | Source | Cost on device | Failure handling |
|---|---|---|---|
| L1-30 | authored knob rows (4.2), baked with metrics, hand-reviewed screenshots | parse 0.5 ms | build fails |
| L31-150 | formula knobs (4.3), baked with metrics | parse | build widens window, then fails |
| L151+ | runtime `generate(branch, L, 30, 40k)`, no metrics, cached | <= 30 x 240 ms worst case, typically 1-3 attempts | fallback: baked `101 + ((L-151) mod 50)` transformed with seed `tail-<L>` |

- Runtime generation is precomputed: while level L is played (L >= 150), level L+1 is generated in slices of <= 4 ms
  inside rAF frames (timed) or a 50 ms `setTimeout` chain (relaxed idle), paused while a pointer is down or an
  animation runs. Result stored in `supermarketSorter.v1.tail` (last 4 levels per branch, ~1 KB).
- If the player arrives before it is ready, the card "Regal wird eingeräumt..." shows a progress bar and generation
  runs at 12 ms per frame. Determinism forbids a wall-clock cutoff; the worst case is bounded by attempts x nodes
  (30 x 40k = 1.2M nodes, about 5 s on an old phone, expected < 0.5 s).
- Build asserts on the L141-150 band that the runtime gate (40k nodes, no metrics) passes within 3 attempts on 95% of
  seeds; if not, the cap band's layer sizes are reduced in `knobs()` until it does.

## 4. Levels

### 4.1 Structure

- Saw-tooth per 10 levels: `idx = (L-1) % 10`; idx 0 = Pause (breather, from L11), idx 4 = Schwer, idx 9 = Sehr schwer,
  others Normal; L1 = Tutorial. Schwer and Sehr schwer show a red "Schwer" badge on the level card and in the HUD.
- Locks never on Pause, Schwer or Sehr schwer levels (difficulty does not stack); bunnies only on Schwer/Sehr schwer.
- New mechanic levels (coach marks, 7.6): layers L2 (both), lock L8 (relaxed) / L15 (timed), side lanes L12 static
  (relaxed) / L6 moving (timed), bunny L15 (both), 4th layer L20 (relaxed), horizontal lane L30 (timed), moving lanes
  in relaxed L31.
- Level data stores **structure + par only**. Speed, time limit, lane direction and product skin are derived at
  runtime (D13).

### 4.2 Authored opening L1-30

"Authored" means: each of L1-30 has a hand-written knob row in `levels.js` (`OPENING.relaxed[L]`,
`OPENING.timed[L]`, 16 integers each, exactly the values in the tables below), the build generates 200 candidates per
level, keeps the one whose metrics sit closest to the middle of the acceptance window, and writes a 390x844 preview
PNG per level to `docs/preview/levels/` for a human pass. Any level can be pinned to a specific attempt number in
`scripts/level-pins.json` after review. Columns: Rack = shape (C); F0 = empty front slots at start; Layers = "L2
n x lo-hi" (layer 2 on n compartments, sizes lo..hi) and "L3-d n x lo-hi" (layers 3..d on n compartments); Side
lanes = "2 x cells static" or "@ cells/s"; Items = expected total (centre + lanes), rounded to a multiple of 3.

### 4.3 Formulas for L31+ (`knobs(branch, L)`, pure, integer except speed)

```js
var tag = L === 1 ? 't' : [ 'b','n','n','n','h','n','n','n','n','v' ][(L - 1) % 10];
var rel = branch === 'relaxed', n = L - 31, C = tag === 'b' ? 9 : 10;          // shape 4+t+b, breather 4+t
F0     = rel ? (tag === 'v' || L >= 51 ? 3 : 4) : (tag === 'v' ? 3 : 4);
layer2 = { on: C, lo: tag === 'v' ? 2 : 1, hi: tag === 'b' ? 2 : (rel || tag !== 'n' ? 3 : 2) };
depth  = rel ? min(6, 3 + floor((L - 21) / 20)) : (L < 61 ? 3 : 4);  if (tag === 'b') depth = max(2, depth - 1);
deepN  = min(C, (rel ? 4 + floor(n / 5) : 3 + floor(n / 10)) + (tag === 'h' ? 2 : 0));   // comps with layers 3..depth
deepSz = { lo: 1, hi: tag === 'h' ? 3 : 2 };
locks  = tag === 'n' ? (rel ? (L < 61 ? 2 : 3) : (L < 61 ? 1 : 2)) : 0;   lockN = 4;
lanes  = 2;  cells = speed > 0 ? rows + 3 : rows;                          // rows = 6 (5 on breathers)
types  = min(items / 3, rel ? min(30, 18 + floor(n / 5)) : min(26, 16 + floor(n / 6)));
bunny  = tag === 'h' ? 1 : tag === 'v' ? (L >= 60 ? 2 : 1) : 0;
hLane  = timed only: tag 'v' && L >= 30 -> appearAt 0; tag 'h' && L >= 40 -> 6; L >= 60 && tag 'n' -> max(4, 8 - floor((L-60)/30)); cells 9
```

Beyond L150 the same formulas run, with these caps (they keep the runtime gate inside its budget, 3.7): relaxed
depth 6, deepN <= 10, types 30, locks 3, F0 >= 3; timed depth 4, types 26, locks 2. Relaxed keeps hardening after
the caps only through F0 = 3 on all non-breathers from L151 and lockN 4 -> 5 from L201; timed keeps hardening
through speed (cap 1.0 cells/s at L81) and time (`sPerItem` floor 2.5 s from L61, then the pace check below).

### 4.7 Level identity and transforms

- Board structure = f(branch, L). Relaxed restart shows the identical board (per-level bests compare like for like).
- Timed: each run draws `runSeed`; every level of that run applies `transform(level, hash(runSeed, L))` (type relabel,
  permutation of the 2-column compartments among themselves, swap of top/bottom singles, lane cell rotation). Same
  difficulty, par and time; layouts cannot be memorised. The current `'run-' + seed + '-' + mode + '-' + levelNo`
  seed in `states.js` is removed.
- Product skin: type code -> product id by a seeded pick (`skin-<branch>-<L>`) from the portrait core of
  `SS.catalog` (classes bottle, carton, can, jar, bag, box); no two products of the same colour family below L10,
  at most 2 confusable pairs from L20.

## 5. Scoring and highscore

### 5.1 Timed ("Gegen die Zeit"): an arcade run

| Item | Rule | Config key |
|---|---|---|
| Match | `100 * mult`, `mult = min(4, 1 + 0.5*(chain-1))` (x4 at chain 7) | `MATCH_POINTS 100`, `COMBO_STEP 0.5`, `COMBO_MAX 7` |
| Combo window | 5000 ms, refilled by each match, drains in `tick`, paused with the game, not by Freeze | `COMBO_WINDOW_MS 5000` |
| Bunny spend | 0 points, chain unchanged | |
| Level clear | +250 | `LEVEL_CLEAR_POINTS` |
| Time bonus | `5 * floor(secondsLeft)`; 0 if "+30 s" was taken | `TIME_BONUS_PER_S` |
| Unused bunny | +200 each at clear | `BUNNY_LEFT_POINTS` |
| Flawless | +250 if no undo, no freeze, no extension in the level | `FLAWLESS_POINTS` |
| Stars | `f = timeLeft / timeLimit` at clear: f >= 0.50 -> 3, >= 0.25 -> 2, else 1; extension used -> 1 | `STAR_F` |

- **Run:** starts at L1 with score 0; each cleared level adds its level score; match points of the level in progress
  count when the run ends. **Ends** on the second timeout in a level, on "Lauf beenden" (timeout card, stuck banner,
  pause menu, armed 2 s confirm) or when "Neuer Lauf" replaces it. Undo restores score (no farming: undone matches
  give their points back), the clock never comes back.
- **Recorded** when it ends: `save.recordRun(save, 'timed', {score, level: lastCleared, date})` -> top 10 (existing
  code), plus `bestLevel`, `bestChain`, `games`. A run interrupted by reload is not ended; "Weiterspielen" restores it.
- **Retry:** there is no level retry inside a timed run (the run is the unit). After run over: "Neuer Lauf" (L1, new
  runSeed) or "Zum Menü".

### 5.2 Relaxed ("Entspannt"): a campaign

| Item | Rule |
|---|---|
| Level score | `round(1000 * min(1, par / moves))` (board-size independent) |
| Stars | `moves <= par` -> 3, `moves <= ceil(1.5*par)` -> 2, else 1 (existing `score.stars`) |
| Combo | R13 3-move window; feedback only (sound, popup "Kombo xN", chain 5 -> +1 bunny); not scored |
| Flawless | badge only (no undo, no hint) |
| Records | `levels[L] = { best, stars, moves, flawless }`, best attempt per level only |
| Headline | "Level erreicht" (highest unlocked), "Sterne" (sum of best stars), "Punkte" (sum of best level scores) |

- Retry = "Neu starten" (identical board), always free, never recorded as a loss. Stuck -> undo or restart.
- Replaying an earlier level: from the clear card ("Nochmal") only; no level grid in v1 (8: smallest change).

### 5.3 Save (`save.js`, schema v2)

```js
{ v: 2, muted, music, lowGfx, haptics, lang, reducedMotion, seenTips: { layers, lock, lane, bunny, hlane, moving },
  records: {
    timed:   { best, bestLevel, bestChain, games, top: [{score, level, date}] /* 10 */ },
    relaxed: { reached, totalStars, totalBest, levels: { "<L>": { best, stars, moves, flawless } } } } }
```

`normalizeSave` keeps v1 timed records, maps v1 relaxed `top` to `reached = max(level) + 1`; `mergeSave` takes
max per field and per level. ~30 bytes per relaxed level.

### 7.4 Drag and tap with moving targets

- Pointerdown on a lane: `lanes.hit(clientX, clientY)` reads `getBoundingClientRect()` of the lane's cells (<= 15
  rects, once per pointerdown) and returns `{lane, cell}`; the visible rendering decides, so CSS and JS clocks can
  never disagree. Hit slop: rect inflated by 8 px.
- Grab detaches immediately: the `<img>` is reparented to `#items` at its current board position and follows the
  finger; the cell shows "empty, waiting" (no bars yet). Valid drop -> `game.takeItem` -> `bar`. Invalid drop -> the
  img flies 180 ms to the cell's *current* rect (read at drop time), then is reparented back.
- Tap mode: tap a lane item = select (gold outline on the cell, it keeps moving); tap a compartment = take. If the
  selected cell has left the window by then, refuse with toast "Das Produkt ist weggefahren" and deselect.
- Drop targets are always the static centre compartments, so aiming never involves a moving target.
- `moves` and undo entries are created only by valid drops (R3).

## 9. Test and tuning plan

### 9.1 Bots

| Bot | Branch | Policy | Measures |
|---|---|---|---|
| Witness | both | certificate replay | correctness (must clear 100%) |
| Casual | relaxed | integer-softmax agent (3.3), no lookahead, no undo, sees front + dimmed layer + visible lane cells | win rate (acceptance windows 3.5), dead-end rate, moves/par |
| Casual-timed | timed | same + pace `max(1.8, 3.0-0.02(L-1))` s per move + real lane waits from the speed and phase | % time left (target 20%+ on 18/20 seeds), timeouts |
| Expert | both | solveP with lookahead, 1 s per level | lower bound on moves (par sanity: par >= expert x 1.0) |
| Soak | both | `solver.nextMove` through the real UI | errors, leaks, frame times |

### 9.2 Acceptance thresholds

- Every baked level: certificate replays; invariants G1-G9; window hit (3.5) or logged widening.
- Tail L151-2000 (proof run): 100% emitted levels replay; fallback rate <= 2%; p95 attempts <= 3.
- Timed: casual-timed bot >= 20% time left on 90% of seeds L1-150; no level under 90 s; L1-10 >= 45% left median.
- Relaxed: casual bot win rate never below the window floor; median `moves/par` 0.9-1.2.
- Performance: browser test frame p95 <= 20 ms at CPU x4; action handler p95 <= 8 ms; idle relaxed = 0 rAF/s.
- Unit tests: all old 32 plus about 45 new, `npm test` < 10 s.

### 9.3 iPhone playtest checklist (owner and mother, Safari, from S3 and from file:// via AirDrop'd zip where possible)
