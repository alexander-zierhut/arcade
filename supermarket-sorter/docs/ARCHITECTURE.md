# Architecture

A browser game with no build step: `index.html` loads plain `<script>` files in a fixed order and every file
adds its part to one global namespace, `SS`. The game runs from `file://`, from a local static server and
from an S3 bucket. Same conventions as cocktail-merge (see `docs/RESEARCH.md` section 7 once it exists).

`P` = pure: attaches to `SS` in the browser and to `module.exports` under Node, never touches `window`
or the DOM, so `tests/*.test.js` run the real rules in Node.

## State machine (app/states.js)

`BOOT -> TITLE -> INTRO -> PLAY <-> PAUSE`, `PLAY -> WIN -> INTRO (next level)`, timed: `PLAY -> TIMEOUT -> PLAY (+30 s once)
| LOSE (the Serie is banked) -> INTRO (same level)`. "Kein Platz mehr" is a sheet over PLAY (undo, bunny, restart).
Progress per mode is the reached level in the save; the board in progress is stored per mode after every action and on
hide, so choosing the mode again restores it after a reload.

## Data flow

1. `ui/board.js` turns a pointer gesture into `onDrop(itemId, compIndex, slotIndex)`, `onCollect(itemId)` or
   `onSpend(compIndex)`; belt picks read the cells' live rects once per pointerdown.
2. `app/states.js` calls `SS.game.act(...)`, which applies the move, resolves reveals, cascades, the orphan sweep and
   thresholds (`board.resolve`) and returns events (`move`, `take`, `bar`, `match`, `reveal`, `lockTick`, `unlock`,
   `beltAppear`, `sweep`, `collect`, `spend`, `bunnyEarned`, `warnSpace`, `combo`, `score`, `cleared`, `stuck`, ...).
3. Events go to `ui/boardfx.js` (animations), `ui/hud.js` (numbers, buttons), `audio/sounds.js` and back to
   `app/states.js` (win, timeout, stuck sheet, saves).
4. Belt motion is a compositor animation (`ui/belts.js`); the rules see belts as take-only pools without time. The
   frame loop runs only in timed play for the clock (`SS.game.tick`).

## Levels and the proof

`levels.get(mode, n)` returns level n from `levels-data.js` (baked with a witness), from the authored list (L1-L6),
from runtime generation (`gen.generate`, deterministic per (mode, n)) or, as a last resort, a remix of a baked level.
Every path re-verifies the witness through the real board rules before the level is shown; `npm test` replays every
baked witness through an independent checker written from the rules tables as well.

## Persistence

One localStorage key `supermarketSorter.v1` holds settings, seen coach marks and the records per mode (reached level,
the timed Serie, top 10 lists, per-level bests); the board in progress has one key per mode. Everything is per origin.
All access is in try/catch with an in-memory fallback.
